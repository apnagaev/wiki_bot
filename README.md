# Чек-листы из вики в Telegram (Ansible + Docker Compose)

Telegram-бот показывает чек-листы из вики [Outline](https://www.getoutline.com/) и даёт отмечать пункты кнопками. Отметки пишутся прямо в документы вики: что отмечено в боте, видно в вики, и наоборот.

**Инструкция для пользователей бота — [USAGE.md](USAGE.md).** Ниже — установка для администратора.

- Многопользовательский: каждый подключает свой API-ключ вики и свои разделы чек-листов, бот видит ровно то, что видит пользователь
- Несколько разделов на пользователя (свои, семейные, рабочие, до 20): новый добавляется ссылкой, лишний убирается кнопкой
- Список — вложенный документ раздела, пункт — чек-бокс `- [ ] текст`, заголовки `#` показываются разделителями
- Отметить/снять, скрыть отмеченные, снять все отметки (собрать чемодан заново), вложенные разделы, страницы для длинных списков
- При отметке в документе меняется один символ, остальной текст не трогается; если список правили в вики, бот не отметит не тот пункт
- Два узла, active/passive: Telegram опрашивает тот, кто держит advisory lock в PostgreSQL; второй подхватывает за ~15 секунд
- Входящих портов нет, firewall не нужен

```
        Telegram
           │ long polling (только активный узел)
   ┌───────▼──┐      ┌──────────┐
   │ node1    │      │ node2    │   checklistbot (резерв ждёт блокировку)
   └──┬────┬──┘      └──┬────┬──┘
      │    └─────┬──────┘    │
 ┌────▼─────┐    │      ┌────▼──────┐
 │PostgreSQL│◄───┘      │ вики      │  API Outline с ключом пользователя
 │ lock,    │           │ (Outline) │
 │ ключи    │           └───────────┘
 └──────────┘
```

## Структура

```
install_checklistbot.yaml           # плейбук: код, compose, секреты, сборка, поочерёдный запуск, проверка
inventory.example.yml               # пример inventory (группа docker)
vars/checklistbot.example.yml       # все настройки: токен, ключ шифрования, вики, база
tasks/checklistbot-healthcheck.yaml # ожидание healthy и роль узла
files/checklistbot/
  checklistbot.yaml.j2              # docker-compose.yaml
  checklistbot.env.j2               # переменные окружения (0600 на хосте)
  app/                              # код бота (Python 3.12, aiogram 3, asyncpg)
    bot/checklist.py                # разбор и правка markdown-чек-листов
    bot/outline.py                  # клиент API Outline
    bot/storage.py                  # пользователи в PostgreSQL, ключи зашифрованы (Fernet)
    bot/handlers.py                 # команды, кнопки
    bot/__main__.py                 # запуск, блокировка active/passive
tests/                              # pytest: разбор, отметки, гонки, имитация API Outline
```

## Требования

- Хосты Debian/Ubuntu с Docker Engine и плагином `docker compose`, доступ к `api.telegram.org` (или прокси)
- Ansible на управляющей машине (только встроенные модули)
- PostgreSQL, доступный обоим узлам
- Outline, в котором участникам разрешено создавать API-ключи (Настройки → Безопасность)

## Настройка

1. Бот: в [@BotFather](https://t.me/BotFather) `/newbot`, токен — в `checklistbot_telegram_token`.

2. База. На сервере PostgreSQL:
   ```sql
   CREATE USER checklistbot WITH PASSWORD 'длинный-случайный-пароль';
   CREATE DATABASE checklistbot OWNER checklistbot;
   ```
   Таблицу бот создаёт сам. Если вход ограничен `pg_hba.conf`, разрешите пользователю вход с адресов узлов.

3. Inventory и настройки:
   ```bash
   cp inventory.example.yml inventory.yml
   cp vars/checklistbot.example.yml vars/checklistbot.yml
   ```
   В `vars/checklistbot.yml`: токен, адрес вики (`checklistbot_wiki_urls`), база и ключ шифрования:
   ```bash
   openssl rand -base64 32 | tr '+/' '-_'
   ```
   Ключ шифрования одинаковый на узлах и не меняется: после смены сохранённые API-ключи не расшифровать, пользователям придётся прислать их заново.
   Зашифруйте: `ansible-vault encrypt vars/checklistbot.yml`.

## Развертывание

```bash
ansible-playbook -i inventory.yml install_checklistbot.yaml --ask-vault-pass
```

На каждом узле по очереди:
1. Кладёт код бота, `docker-compose.yaml` и `checklistbot.env` (0600).
2. Собирает образ, только если изменился код или образа нет.
3. `docker compose up -d`: контейнер пересоздаётся, только если изменились образ или настройки.
4. Ждёт `healthy` и показывает роль узла: «активный» или «резерв».
5. Удаляет неиспользуемые образы (тома не трогает).

## Как пользоваться

Подробно, с подготовкой списков в вики и разбором сообщений бота, — в [USAGE.md](USAGE.md). Кратко:


1. В вики заведите документ-раздел (например «Checklists»), внутри — документы-списки с чек-боксами. В одном списке можно делать разделы заголовками.
2. В боте `/start`, затем пришлите ссылку на раздел и свой API-ключ вики (Настройки → API → новый ключ, начинается с `ol_api_`). Сообщение с ключом бот сразу удаляет. Если Outline поддерживает ограничение ключа, достаточно `documents.info`, `documents.list`, `documents.update`, `auth.info`.
3. `/lists` — списки с прогрессом; в списке нажатие на пункт отмечает его или снимает отметку.
4. Ещё раздел — просто пришлите ссылку на него. При нескольких разделах `/lists` открывает меню разделов, кнопка «📚 Разделы» возвращает в него.

Команды: `/lists`, `/sections` (разделы: добавить, убрать), `/setup` (сменить ключ, разделы остаются), `/forget` (удалить свои данные из бота; ключ отзовите в вики).

Все разделы пользователя — из одной вики (один ключ). Разделы из разных вики из `checklistbot_wiki_urls` одновременно не подключаются: сначала `/forget`.

Чтобы список был у нескольких человек (семейный «в поездку»), откройте документ им в вики: каждый подключает свой ключ и видит общие отметки.

## Как устроено

- Ссылки принимаются только на вики из `checklistbot_wiki_urls`: бот стоит во внутренней сети и не должен ходить по чужим адресам.
- Отметка: бот читает документ, находит пункт по номеру и сверяет хеш его текста; если пункты сдвинулись — ищет по хешу, если пункт удалён — показывает актуальный список и ничего не меняет. Затем меняет `[ ]` ↔ `[x]` в этой строке и сохраняет документ через `documents.update`.
- Нажатия на один документ выполняются по очереди, быстрые отметки подряд не теряются. Если в ту же секунду документ правят в вики, одна из правок может потеряться: Outline не даёт условного сохранения.
- Таблицы: `checklist_users` (Telegram ID, адрес вики, ключ — зашифрован, настройка «скрывать отмеченные») и `checklist_roots` (разделы пользователя: ID документа и название; название обновляется, когда раздел переименовали в вики). Схему бот создаёт и обновляет сам при старте; данные первой версии (один раздел) переносятся автоматически.
- Active/passive: оба контейнера держат соединение с базой, Telegram опрашивает тот, кто взял `pg_try_advisory_lock`. Обрыв соединения — контейнер выходит, Docker перезапускает его, блокировку берёт другой узел.
- Healthcheck — файл-пульс, обновляется раз в 20 секунд на обоих узлах.


## Обновление

Поменяйте код или версии в `files/checklistbot/app/requirements.txt` и прогоните плейбук: узлы пересобираются по очереди, бот всё время работает на одном из них.

## Диагностика

**Бот не отвечает.** `docker logs checklistbot` на обоих узлах: активный должен быть ровно один. Если оба «резерв» — блокировку держит зависшее соединение; оно снимется, когда PostgreSQL закроет сеанс (или `SELECT pg_terminate_backend(pid) FROM pg_locks WHERE locktype='advisory';`).

**`TelegramConflictError` в логах.** Тем же токеном опрашивает кто-то ещё (старая копия бота). Остановите её.

**«Вики сейчас недоступна».** Контейнер не резолвит или не достаёт до вики: задайте `checklistbot_dns` или проверьте маршрут до адреса вики изнутри контейнера.

**«Вики не принимает ваш API-ключ».** Ключ истёк или отозван: создайте новый и пришлите боту.
